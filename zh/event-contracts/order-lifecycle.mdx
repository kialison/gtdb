CLOB 订单采用混合模式：链下撮合提供速度，链上结算提供无需信任的最终性。本页介绍订单的完整生命周期、可能经历的状态，以及各阶段必须满足的条件。

![图片](/images/image-4.png "图片")

## 订单如何运作

CLOB 上的每个订单本质上都是**限价单**。通常所说的“市价单”，其实是一个定价足够激进、能够立即与订单簿成交的限价单。撮合引擎遵循价格—时间优先原则：更优价格优先成交；价格相同时，先提交的订单优先。

## 订单类型

| 类型 | 行为 | 使用场景 |
| --- | --- | --- |
| `GTC` | 撤销前有效。订单留在订单簿中，直到成交或取消。 | 被动做市 |
| `GTD` | 指定日期前有效。订单保留至明确的到期时间。 | 有时间限制的报价 |
| `FOK` | 全部成交或立即取消。必须立刻全部成交，否则取消。 | 全有或全无成交 |
| `FAK` | 立即成交可成交数量，剩余部分取消。 | 扫取流动性 |

### 只挂单订单

只挂单订单保证作为**挂单方（Maker）**。如果提交后会立即穿过订单簿并吃单，系统将拒绝该订单，而不是让其消耗流动性。

## 订单生命周期

<Steps>
  <Step title="创建并签名">
    使用 Token ID、方向（`BUY`/`SELL`）、价格、数量、到期时间和时间戳构建订单，并由交易钱包使用 EIP-712 签名。
  </Step>
  <Step title="提交至 CLOB">
    CLOB 验证签名，检查余额与授权额度，并校验最小价格变动单位和最小订单数量。无效订单会在进入订单簿前被拒绝。
  </Step>
  <Step title="撮合或挂单">
    可立即成交的订单会与现有流动性撮合。加密货币和金融类涨跌市场会应用 **250ms 吃单延迟**以保护挂单方；体育和游戏市场采用更长延迟。无法立即成交的订单会保留至成交、取消或到期。
  </Step>
  <Step title="结算">
    Exchange 合约验证双方签名，并在一笔原子链上交易中，将结果代币从卖方转给买方、USDT 从买方转给卖方。
  </Step>
  <Step title="确认">
    交易上链并确认后，余额更新，成交记录出现在历史中，成交结果最终确定。
  </Step>
</Steps>

## 订单状态

| 状态 | 含义 |
| --- | --- |
| `live` | 订单正在订单簿中等待撮合 |
| `matched` | 订单已与对手方撮合，正在结算 |
| `delayed` | 订单处于撮合前的吃单延迟窗口 |
| `unmatched` | 订单未成交便离开订单簿（已取消或到期） |

## 成交状态

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| `MATCHED` | 已在链下确认撮合，链上结算排队中 | 否 |
| `MINED` | 结算交易已在链上打包 | 否 |
| `CONFIRMED` | 结算已最终确认，余额已更新 | 是 |
| `RETRYING` | 链上提交失败，运营方正在重试 | 否 |
| `FAILED` | 结算永久失败 | 是 |

## Maker 与 Taker

| 角色 | 说明 |
| --- | --- |
| Maker | 将订单挂在订单簿中，为市场提供流动性 |
| Taker | 穿过订单簿成交，消耗流动性 |

\*\*价格改善：\*\*吃单方按订单簿中的挂单价格成交，而不是按自己的限价成交。例如，以 0.55 美元买入、与 0.52 美元卖单匹配时，成交价为 **0.52 美元**。

## 取消订单

你可以随时取消任何挂单，但吃单延迟窗口内除外。已部分成交的部分无法取消：订单一旦有部分完成撮合，该部分无论如何都会结算。

## 要求

| 要求 | 说明 |
| --- | --- |
| 余额 | 提交时拥有足够的 USDT（买单）或结果代币（卖单） |
| 授权额度 | 必须授权 Exchange 合约转移相关资产 |
| API 凭证 | 调用认证接口需要有效的 API Key、Secret 与 Passphrase |

单笔新订单可提交的最大数量为：

```text
maxOrderSize = balance − ∑(openOrderSize − filledAmount)
```
