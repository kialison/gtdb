事件合约 CLOB 采用混合模式：订单撮合在链下完成以获得更高效率，最终资产交割在链上执行。下面介绍订单从创建到结算的完整生命周期。

![Image](/images/image-4.png "Image")

## 订单如何工作

CLOB 中底层都可以视为限价订单。通常所说的“市价单”，本质上是一个价格足够激进、能够立即穿过订单簿成交的限价订单。

撮合遵循价格优先、时间优先：更优价格优先成交；同一价格下，更早进入订单簿的订单优先。

## 订单有效方式

| 类型 | 行为 | 典型场景 |
| --- | --- | --- |
| `GTC` | Good-Til-Cancelled，直到成交或主动撤销前持续有效 | 挂单、做市 |
| `GTD` | Good-Til-Date，到指定时间自动失效 | 有有效期的报价 |
| `FOK` | Fill-Or-Kill，必须立即全部成交，否则全部取消 | 全成或全撤 |
| `FAK` | Fill-And-Kill，立即成交可成交部分，其余取消 | 快速吃单 |

### Post Only

Post Only 订单保证只作为 Maker。如果提交时会立即与现有订单成交，则订单直接被拒绝，而不会主动吃掉流动性。

## 完整生命周期

<Steps>
  <Step title="创建并签名">
    构造订单参数，包括 Token ID、方向（`BUY` / `SELL`）、价格、数量、过期时间和时间戳，并使用交易钱包签名。
  </Step>
  <Step title="提交到 CLOB">
    CLOB 验证签名、余额与授权，并校验 tick size、最小下单数量等交易规则。不合法订单不会进入订单簿。
  </Step>
  <Step title="撮合或进入订单簿">
    可立即成交的订单与现有流动性撮合；无法立即成交的订单继续留在订单簿，直到成交、撤销或过期。部分市场可能对 Taker 设置撮合延迟保护 Maker。
  </Step>
  <Step title="链上结算">
    撮合完成后，结算合约验证订单并在一次原子交易中完成结果代币与 USDT 的资产交割。
  </Step>
  <Step title="确认完成">
    链上交易确认后，账户余额、成交记录和持仓同步更新。
  </Step>
</Steps>

## 订单状态

| 状态 | 含义 |
| --- | --- |
| `live` | 订单位于订单簿中，可继续参与撮合 |
| `matched` | 已与对手方匹配，正在进入结算流程 |
| `delayed` | 处于 Taker 延迟窗口 |
| `unmatched` | 未成交离开订单簿，例如被取消或到期 |

## 成交状态

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| `MATCHED` | 链下撮合已确认，等待链上结算 | 否 |
| `MINED` | 结算交易已上链 | 否 |
| `CONFIRMED` | 结算最终确认，余额已更新 | 是 |
| `RETRYING` | 链上提交失败，系统正在重试 | 否 |
| `FAILED` | 结算最终失败 | 是 |

## Maker 与 Taker

| 角色 | 说明 |
| --- | --- |
| Maker | 挂单并提供流动性 |
| Taker | 主动跨过订单簿、消耗已有流动性 |

Taker 实际成交价格按照订单簿上对手方的挂单价格执行。例如买单限价为 `$0.55`，与 `$0.52` 的卖单成交时，成交价为 `$0.52`。

## 撤单

未成交订单通常可主动取消。已经完成撮合的部分无法撤回；即使剩余部分被撤销，已撮合部分仍会继续完成结算。

## 下单要求

| 要求 | 说明 |
| --- | --- |
| Balance | 买入需要足够 USDT，卖出需要足够结果代币 |
| Allowance | 对应合约需要获得资产转移授权 |
| API credentials | 私有交易接口需要有效认证信息 |

单笔新订单最大可用数量应扣除现有未成交订单已占用的余额：

```text
maxOrderSize = balance − ∑(openOrderSize − filledAmount)
```
