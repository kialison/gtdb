CLOB 上的订单遵循混合模式：撮合在链下进行以确保速度，而结算在链上执行以实现无需信任的终局性。本页面将带你了解订单的完整生命周期、订单可能经历的状态，以及每个步骤必须满足的要求。

## 订单如何运作

CLOB 上的每个订单都是**限价单**。人们所说的"市价单"实际上只是一个定价激进、能立即穿越订单簿的限价单。撮合引擎按价格-时间优先规则执行：更优价格先成交，相同价格下最早提交的订单先成交。

## 订单类型

| 类型 | 行为 | 使用场景 |
| --- | --- | --- |
| `GTC` | Good-Til-Cancelled。在订单簿中挂单，直到成交或被取消。 | 被动做市。 |
| `GTD` | Good-Til-Date。挂单至明确的到期时间戳为止。 | 有时间限制的报价。 |
| `FOK` | Fill-Or-Kill。必须立即全部成交，否则取消。 | 全有或全无的吃单。 |
| `FAK` | Fill-And-Kill。尽可能立即成交，剩余部分取消。 | 横扫流动性。 |

### 仅挂单（Post-only）订单

Post-only 订单保证为**挂单方**。如果 post-only 订单在提交时会穿越订单簿，它将被拒绝，而不会吃掉流动性。

## 订单生命周期

<Steps>
  <Step title="创建并签名">
    构建订单载荷，包含 Token ID、方向（`BUY`/`SELL`）、价格、数量、过期时间和时间戳。使用你的交易钱包通过 EIP-712 进行签名。
  </Step>
  <Step title="提交至 CLOB">
    CLOB 验证签名、检查余额和授权额度、并强制执行最小价格变动单位和最小数量规则。无效订单在触及订单簿前即被拒绝。
  </Step>
  <Step title="撮合或挂单">
    可成交订单与挂单流动性进行撮合。加密货币和金融类涨跌市场采用 **250ms 吃单延迟**以保护挂单方；体育和游戏市场采用更长的延迟。不可成交订单将挂单，直到被撮合、取消或过期。
  </Step>
  <Step title="结算">
    Exchange 合约验证双方签名，在单笔原子链上交易中完成结果代币从卖方到买方、以及 USDT 从买方到卖方的划转。
  </Step>
  <Step title="确认">
    交易被打包并确认后，余额更新，交易出现在历史记录中，成交即告最终确定。
  </Step>
</Steps>

## 订单状态

| 状态 | 含义 |
| --- | --- |
| `live` | 订单正在订单簿中挂单，可参与撮合。 |
| `matched` | 订单已与对手方撮合，正在结算中。 |
| `delayed` | 订单处于吃单延迟窗口中，等待撮合。 |
| `unmatched` | 订单已离开订单簿但未成交（已被取消或已过期）。 |

## 交易状态

| 状态 | 含义 | 是否为终态 |
| --- | --- | --- |
| `MATCHED` | 链下撮合已确认；链上结算已排队。 | 否 |
| `MINED` | 结算交易已在链上被打包。 | 否 |
| `CONFIRMED` | 结算已最终确定。余额已更新。 | 是 |
| `RETRYING` | 链上提交失败；操作员正在重试。 | 否 |
| `FAILED` | 结算永久失败。 | 是 |

## 挂单方与吃单方

| 角色 | 说明 |
| --- | --- |
| 挂单方（Maker） | 通过在订单簿上挂单提供流动性。 |
| 吃单方（Taker） | 通过穿越订单簿吃掉流动性。 |

**价格改善：** 吃单方按挂单价格成交，而非自己的限价。一个在 $$0.55 的买单匹配到 $$0.52 的卖单，将以 **\$0.52** 成交。

## 取消订单

你可以随时取消任何挂单中的订单，除了处于吃单延迟窗口期间。部分成交的订单无法取消：一旦订单的一部分已经撮合，该部分成交将照常结算。

## 要求

| 要求 | 说明 |
| --- | --- |
| 余额 | 提交时具有足够的 USDT（买单）或结果代币（卖单）。 |
| 授权额度 | Exchange 合约必须被批准划转相应资产。 |
| API 凭证 | 已认证接口需要有效的 API Key、Secret 和 Passphrase。 |

单笔新订单的最大下单数量为：

```text
maxOrderSize = balance − ∑(openOrderSize − filledAmount)
```
