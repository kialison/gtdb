在确认 Market 当前接受订单后，可以针对指定 Outcome Token 提交交易。公开市场数据无需认证；下单属于私有操作，需要完成认证。

生产环境 Base URL：

```text
https://api.dexbuilder.com
```

## 1. 读取 Market 交易限制

先查询 Market，并从 `outcomes[].token_id` 中选择要交易的 Token：

```bash cURL
curl "https://api.dexbuilder.com/api/v4/prediction/markets/<market_id>"
```

再读取公开订单簿：

```bash cURL
curl "https://api.dexbuilder.com/api/v4/prediction/tokens/<token_id>/order_book?depth=20"
```

提交订单前应根据响应中的 `min_order_size` 和 `tick_size` 做数量和价格校验。

## 2. 提交订单

```bash cURL
curl -X POST "https://api.dexbuilder.com/api/v4/prediction/orders" \
  -H "Content-Type: application/json" \
  -H "<authentication-header>: <authentication-value>" \
  --data '{
    "token_id": "<token_id>",
    "side": "BUY",
    "price": "0.52",
    "size": "10",
    "total_cost": "5.20",
    "order_type": "LIMIT",
    "order_mode": "GTC",
    "client_order_id": "client-order-001",
    "post_only": false,
    "sell_all": false,
    "expire_time": 0
  }'
```

<Note>
上例认证 Header 仅用于表示接口需要认证，实际公开认证方案以正式认证文档为准。不要把内部网关身份 Header 用作客户端认证参数。
</Note>

## 请求字段

| 字段 | 说明 |
| --- | --- |
| `token_id` | 要交易的 Outcome Token |
| `side` | 订单方向，例如 `BUY` / `SELL` |
| `price` | 限价，decimal string |
| `size` | 下单数量，decimal string |
| `total_cost` | 某些订单模式下使用的订单总成本 |
| `order_type` | 交易服务定义的订单类型 |
| `order_mode` | Time-in-force / 执行模式 |
| `client_order_id` | 可选的客户端幂等 / 跟踪 ID |
| `post_only` | 是否只作为 Maker 提供流动性 |
| `sell_all` | 卖出时是否使用全部可用持仓 |
| `expire_time` | 适用时的过期时间，Unix 秒 |

## 接受响应

```json
{
  "order_id": "order-123",
  "client_order_id": "client-order-001",
  "status": "ACCEPTED",
  "created_at": 1782753357
}
```

`ACCEPTED` 只表示订单请求已被系统接受，并不代表已经全部成交。后续应通过订单查询接口读取实际状态。

## 下单前检查

- Market 必须满足 `accepting_orders: true`；
- `token_id` 应来自 Market 的 `outcomes` 数组；
- `size` 必须满足 `min_order_size`；
- `price` 必须符合 `tick_size`；
- 价格、数量、金额建议始终使用字符串，避免浮点精度误差；
- 私有请求必须使用正式认证方案。
