## 当前已经有 Builder API 吗？

当前 API Reference 主要是面向交易用户的 PerpDEX OpenAPI。项目方专属的 Builder API 还会继续补充，例如手续费、运营数据、用户统计、返佣等能力。

## Builder 项目方现在怎么做运营管理？

通过独立的 **Builder 运营后台**。后台提供运营数据、用户、交易量、邀请返佣、公告、资金及权限管理等项目级能力。

## 为什么运营后台和 OpenAPI 要分开？

两者的使用对象和权限不同：OpenAPI 主要服务用户侧交易流程；运营后台面向项目方管理员，包含更高权限的业务和资金管理能力。

## Builder 可以直接调用现有 PerpDEX OpenAPI 吗？

可以。用户侧行情、账户、订单、仓位等交易能力统一使用现有 PerpDEX API。具体可用接口以 API Reference 为准。

## Builder 可以获取自己用户和交易量数据吗？

运营后台提供对应的数据查询和统计能力。后续如开放 Builder 数据 API，项目方也可以将这些数据同步到自己的 BI 或运营系统。

## 手续费和收益怎么查询？

当前可以通过运营数据看板查看手续费相关数据。具体费率、分成和结算规则以项目实际配置为准；相关 Builder API 后续单独开放。

## 邀请返佣在哪里管理？

通过运营后台的邀请返佣模块进行管理和查看。具体返佣规则、比例和结算方式以项目配置为准。

## 充值、提现问题在哪里排查？

运营后台提供充值记录和提现记录查询，并可结合对应链上或系统状态进一步排查。

## 如何控制不同运营人员的后台权限？

通过后台的管理员和角色管理进行权限配置。建议按最小权限原则划分运营、财务、客服和管理员权限，并使用操作日志进行审计。

## Builder API 上线后会放在哪里？

会在 **API Reference** 中新增独立的 Builder API 分类，与普通用户交易接口区分。
