title: "选择接入方式"
description: "根据项目现有前端、开发资源和定制需求确定 DexBuilder 接入方案。"

在正式开发前，Builder 需要先确认产品层与基础设施层的分工。不同项目可以采用不同接入深度，但核心目标一致：**由 Builder 负责自己的产品体验，由 DexBuilder 提供底层交易能力。**

## 常见接入方式

### 使用现有前端资源

适合希望较快上线、并优先复用现有产品能力的项目。

项目方重点完成：

- 品牌与页面配置
- 域名及环境配置
- 产品范围确认
- 运营策略与上线验收

<Info>
现有前端资源的可复用范围，以项目实际对接方案为准。
</Info>

### 自研前端 + OpenAPI

适合已有钱包、交易平台或希望高度定制交易体验的项目。

项目方需要自行完成：

- 账户与认证流程
- 行情与交易页面
- 资产、订单和仓位展示
- API / WebSocket 接入
- 异常处理、状态同步和前端风控提示

DexBuilder 提供底层账户、资产、行情、交易、风险和结算能力。

## 如何选择

| 维度 | 复用现有前端资源 | 自研前端 + OpenAPI |
| --- | --- | --- |
| 上线速度 | 较快 | 取决于开发周期 |
| UI 定制 | 中 | 高 |
| 交易流程定制 | 中 | 高 |
| 项目开发工作量 | 较少 | 较多 |
| 适合项目 | 快速上线 | 钱包、交易平台、专业开发团队 |

## 下一步

接入方式确认后，建议按照以下顺序推进：

1. 账户与认证
2. 充提与资产
3. 交易接入
4. 实时数据
5. Builder 配置
6. 联调与上线
