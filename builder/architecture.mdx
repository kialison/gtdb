---
title: "DexBuilder 架构"
description: "了解 Builder 项目方与 DexBuilder 基础设施之间的职责边界。"
---

DexBuilder 的目标不是替项目方运营一个 DEX，而是提供构建交易产品所需的底层交易基础设施。Builder 在此基础上完成自己的品牌、前端、用户入口和运营体系。

## 职责边界

```text
Builder 项目方
  ├─ 品牌与域名
  ├─ 前端产品与交互
  ├─ 用户入口与增长
  ├─ 运营策略
  └─ 项目级配置
          │
          ▼
      DexBuilder
  ├─ 账户与认证能力
  ├─ 充值 / 提现 / 资产
  ├─ 行情与市场数据
  ├─ 订单与撮合
  ├─ 仓位与保证金
  ├─ 风控与强平
  ├─ 结算
  └─ Builder 管理能力
```

## Builder 需要负责什么

Builder 需要根据自己的产品定位完成用户可见的产品层，包括品牌、页面、交易入口、运营活动及用户服务等内容。

如果采用自研前端，Builder 还需要负责：

- API 与 WebSocket 的接入
- 前端状态管理和异常处理
- 交易确认与风险提示
- 账户、资产、订单和仓位展示
- 线上监控及用户问题排查

## DexBuilder 提供什么

DexBuilder 提供交易产品运行所需的核心底层能力，Builder 无需自行建设完整的撮合、账户和风险体系。
