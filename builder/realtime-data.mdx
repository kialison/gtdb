title: "实时数据"
description: "项目方如何使用实时数据保持行情、订单、成交与仓位状态同步。"
---

交易产品不能只依赖 REST 查询。Builder 需要使用实时数据持续同步用户侧状态，确保行情和交易反馈及时更新。

## 典型实时数据

Builder 通常需要关注：

- 行情和盘口变化
- 市场成交
- 订单状态变化
- 用户成交回报
- 仓位变化
- 账户及风险状态变化

## 推荐架构

```text
REST API
  └─ 初始化页面状态

WebSocket
  └─ 持续接收实时变化
        ↓
Builder 状态层
        ↓
交易页面 / 资产页面 / 订单与仓位
```

## Builder 需要处理

### 初始化与增量更新

页面首次加载时先获取完整状态，再通过 WebSocket 接收增量变化，避免只依赖推送导致数据不完整。

### 断线重连

连接中断后应自动重连，并重新拉取关键状态，防止断线期间的数据变化丢失。

### 顺序与重复消息

项目方需要根据协议设计去重、状态覆盖和异常恢复逻辑，避免旧状态覆盖新状态。

### 用户体验

网络异常、数据延迟或连接断开时，应在前端明确提示，而不是继续展示可能已经过期的交易状态。

<Note>
具体 WebSocket 地址、认证方式、频道和消息格式，以对应产品的实时数据文档为准。
