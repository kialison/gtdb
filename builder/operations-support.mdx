DEX 上线并不代表接入结束。Builder 需要建立自己的日常监控、问题反馈和故障处理机制，保证用户侧产品持续可用。

## Builder 日常需要关注

- API 和 WebSocket 可用性
- 行情、订单、仓位和资产状态
- 充值与提现异常
- 用户交易失败率
- 页面错误和异常日志
- 项目运营数据
- 后台管理员及权限变化

## 问题定位建议

当用户反馈交易或资产问题时，建议先确认：

1. 用户及账户标识
2. 发生时间
3. 网络与环境
4. 交易对或资产
5. Order ID / Transaction Hash 等业务标识
6. 请求结果、错误码和前端日志
7. 是否可以稳定复现

完整的上下文可以显著降低双方定位问题的时间。

## Builder 与 DexBuilder 的支持边界

### Builder 负责

- 自有前端和产品逻辑
- 用户侧页面与交互
- 自有服务和网络
- 项目运营及用户沟通
- 第一轮问题收集与定位

### DexBuilder 负责

- 已开放底层能力的运行支持
- DexBuilder 侧 API、交易和基础设施问题定位
- 项目接入阶段的技术协同
- 平台级异常的状态同步

## 重大异常

涉及交易中断、资产异常或大面积用户影响的问题，应优先确认影响范围并及时升级处理，避免只通过普通用户反馈逐个排查。

具体支持渠道、响应流程和联系人以项目正式合作配置为准。
