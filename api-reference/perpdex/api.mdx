# 通用说明

## HTTP 通用格式

- 所有读操作使用 `GET` 方法，只接收请求参数，不读取请求体。
- `DELETE` 用于删除指定资源；复杂删除操作可使用 `POST` 并通过请求体传参。
- 更新操作使用 `POST`、`PUT` 或 `PATCH`，具体参数位置以接口页面为准。
- 请求成功返回 `2xx`；`401` 表示认证失败；其他 `4xx` 表示请求无效；`5xx` 表示服务端处理异常。

## 时间

除接口另有说明外，时间字段统一使用 Unix 时间戳。签名请求中的 `Timestamp` 使用 Unix 秒级时间戳。

## 网关入出站时间

如响应中提供网关处理相关时间字段，以实际返回值为准，可用于定位请求在网关和服务端的处理耗时。

## 分页

列表接口通常通过以下参数分页：

| 参数 | 说明 |
| --- | --- |
| `limit` | 单次返回的最大记录数量 |
| `offset` | 列表偏移量，从 `0` 开始 |

部分时间范围接口同时支持 `from`、`to` 参数。

## 限频规则

Perp DEX 的单笔/批量下单、改单、撤单等交易请求按服务端限频规则执行。超过限制时可能返回 `429`。客户端应避免短时间重复提交同一请求，并根据返回结果控制重试频率。

## 返回格式

接口默认使用 JSON 返回数据。具体字段结构、数组或对象类型以对应接口页面的 Response Schema 为准。

## 数据类型

常见数据类型包括：

- `string`：字符串；价格、数量、金额等高精度数值通常使用字符串返回。
- `integer`：整数，例如 ID、时间戳或档位。
- `number`：数值，例如部分统计值或带小数时间字段。
- `boolean`：布尔值。
- `array`：数组。
- `object`：对象。

## Trace Id

如 API 响应 Header 中返回 `X-Trace-ID`，可在问题排查时提供该值用于请求链路定位。

## Self-Trade Prevention (STP)

部分订单字段中保留 `stp_act`、`stp_id` 等 STP 相关参数。具体是否生效以当前 PerpDEX 交易系统实际支持情况为准。

常见策略：

| 值 | 含义 |
| --- | --- |
| `cn` | Cancel new，取消新订单 |
| `co` | Cancel old，取消旧订单 |
| `cb` | Cancel both，同时取消新旧订单 |
| `-` | 不启用 STP |

## 异常处理

调用失败时建议保留以下信息用于排查：请求 Method、Request URI、Query 参数、Request Body、HTTP 状态码、返回内容及 `X-Trace-ID`（如有）。

<Warning>
排查问题时不要提供 API Secret，也不要在公开环境中暴露完整认证信息。
</Warning>

## 异常 Label 列表

业务异常的具体 Label 和错误信息以 API 实际返回内容为准。客户端应优先根据 HTTP 状态码和返回的错误字段进行处理。
