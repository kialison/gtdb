DexBuilder 將用戶體驗層與底層交易及運營服務分離。項目方可以保留自己的界面與品牌，同時接入一致的市場、賬戶、交易、資產與 Builder 能力。

## 架構分層

| 層級 | 作用 |
| --- | --- |
| 交易體驗層 | 由項目方擁有的 Web 或移動端界面，呈現市場、訂單、倉位、餘額與錢包操作 |
| 接入層 | REST、WebSocket、請求籤名、冪等、權限與 API 客戶端生成 |
| 交易服務層 | 行情、訂單生命週期、撮合、成交、倉位、保證金模式、資金費率與強平流程 |
| 賬戶與賬本層 | 賬戶狀態、餘額、賬戶流水、交易歷史、手續費與對賬數據 |
| 資產與結算層 | 充值、提現、內部划轉、錢包授權、盈虧結算與 Builder 收入結算 |
| Builder 運營層 | 項目注冊、用戶注冊、配置、活動、推薦關係、手續費設置與管理數據訪問 |

## 參與方

| 參與方 | 職責 |
| --- | --- |
| 交易用戶 | 連接錢包、授權賬戶與資產操作、下單並管理倉位 |
| 項目團隊 | 構建產品體驗，並接入行情、交易、賬戶與資產流程 |
| Builder 運營方 | 配置項目、注冊用戶、管理產品運營並查看 Builder 級數據 |
| 管理員賬戶 | 在權限範圍內鑒權 Builder 操作並管理項目級配置 |
| DexBuilder | 提供底層交易、賬戶、賬本、結算與 Builder 服務 |

## 請求流程

1. 應用讀取公開行情與合約信息；
2. 用戶連接錢包並完成所需的賬戶授權；
3. 已認證請求使用分配給項目或賬戶的接入憑證簽名；
4. 訂單與倉位更新由交易服務處理；
5. 成交、餘額、倉位、手續費與結算事件寫入賬戶和賬本記錄；
6. 應用核對 API 響應、賬戶狀態與資產變動，再向用戶展示最終狀態。

<Note>
  HTTP 成功響應表示請求已按照相應接口的定義被接受或完成。涉及資產移動和結算時，應始終以最終賬戶與賬本狀態完成對賬。
</Note>
