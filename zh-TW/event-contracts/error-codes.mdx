事件合約 API 使用標準 HTTP 狀態碼表示請求處理結果。以下錯誤可能出現在需要認證的介面中。

## `401 Unauthorized`

可能原因包括：未攜帶或使用無效 API Key、簽名不正確、時間戳不符合要求，或簽名內容與實際請求不一致。

排查時重點確認：

- 請求時間戳；
- 簽名原文；
- Query 與 Body 是否和簽名時完全一致；
- API Secret 是否正確。

## `429 Too Many Requests`

表示請求頻率超過目前限頻規則。建議客戶端使用指數退避後重試，並避免短時間內重復請求同一資源。

## `503 Service Unavailable`

表示交易服務或依賴的上游服務暫時不可用。只讀查詢可在短暫等待後重試；交易類請求應先確認上一筆請求的最終狀態，避免重復提交。

## 通用錯誤處理建議

建議記錄 Request Method、Request Path、Query、請求時間戳、`trace_id`、HTTP 狀態碼以及服務端結構化錯誤碼與錯誤資訊。

<Warning>
排查日誌時不要記錄或對外暴露 API Secret、完整簽名金鑰或其他敏感認證資訊。
</Warning>
