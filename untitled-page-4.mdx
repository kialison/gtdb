DexBuilder 将用户体验层与底层交易及运营服务分离。项目方可以保留自己的界面与品牌，同时接入一致的市场、账户、交易、资产与 Builder 能力。

## 架构分层

| 层级 | 作用 |
| --- | --- |
| 交易体验层 | 由项目方拥有的 Web 或移动端界面，呈现市场、订单、仓位、余额与钱包操作 |
| 接入层 | REST、WebSocket、请求签名、幂等、权限与 API 客户端生成 |
| 交易服务层 | 行情、订单生命周期、撮合、成交、仓位、保证金模式、资金费率与强平流程 |
| 账户与账本层 | 账户状态、余额、账户流水、交易历史、手续费与对账数据 |
| 资产与结算层 | 充值、提现、内部划转、钱包授权、盈亏结算与 Builder 收入结算 |
| Builder 运营层 | 项目注册、用户注册、配置、活动、推荐关系、手续费设置与管理数据访问 |

## 参与方

| 参与方 | 职责 |
| --- | --- |
| 交易用户 | 连接钱包、授权账户与资产操作、下单并管理仓位 |
| 项目团队 | 构建产品体验，并接入行情、交易、账户与资产流程 |
| Builder 运营方 | 配置项目、注册用户、管理产品运营并查看 Builder 级数据 |
| 管理员账户 | 在权限范围内鉴权 Builder 操作并管理项目级配置 |
| DexBuilder | 提供底层交易、账户、账本、结算与 Builder 服务 |

## 请求流程

1. 应用读取公开行情与合约信息；
2. 用户连接钱包并完成所需的账户授权；
3. 已认证请求使用分配给项目或账户的接入凭证签名；
4. 订单与仓位更新由交易服务处理；
5. 成交、余额、仓位、手续费与结算事件写入账户和账本记录；
6. 应用核对 API 响应、账户状态与资产变动，再向用户展示最终状态。

<Note>
  HTTP 成功响应表示请求已按照相应接口的定义被接受或完成。涉及资产移动和结算时，应始终以最终账户与账本状态完成对账。
</Note>
