Understanding the fundamental building blocks of Event Contracts.

Every contract is structured around two core concepts: **markets** and **events**. Understanding how they relate is essential for building on the platform.

## Markets

A market is the fundamental tradable unit on event contracts. Each market represents a single binary question with Yes/No outcomes.

<Frame>
  ```mermaid
  flowchart LR
BQ([Binary Question]) -.-> M[Market]
M --> T[Trade]
M --> OB[Order Book]
M --> Y[Y]
M --> N[N]
T --> S[Settlement]
OB --> R[Resolution]
  ```
</Frame>

Every market has:

| Identifier | Description |
| --- | --- |
| Condition ID | Unique identifier for the market's condition in the CTF contracts |
| Question ID | Hash of the market question used for resolution |
| Token IDs | ERC1155 token IDs used for trading on the CLOB, one for Yes, one for No |

### Market Example

A simple market might be:

> _"BTC Up or Down 5m?"_

This creates two outcome tokens:

- **Yes token** — Redeemable for 1 if Bitcoin is up
- **No token** — Redeemable for 1 if Bitcoin isn't up

## Events

An event is a container that groups one or more related markets together. Events provide organizational structure and enable multi-outcome event contracts.

### Single-Market Events

When an event contains just one market, it creates a simple market pair. The event and market are essentially equivalent.

```text
Event: BTC Up or Down 5m?
   └── Market: BTC Up or Down 5m? (Up/Down)
```

## Identifying Markets

Every market and event has a unique slug that appears in the event market URL:

```text
https://app.dexbuilder.com/event/fed-decision-in-october
                            └── slug: fed-decision-in-october
```

You can use slugs to fetch specific markets or events from the API:

```bash
# Fetch event by slug
curl "https://api.dexbuilder.com/api/v4/event_contracts/events/slug/fed-decision-in-october"
```
