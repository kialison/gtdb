Place orders against an outcome token after confirming that the market is accepting orders. Market data is public; order placement is a private operation and requires authentication.

The production API base URL is `https://api.dexbuilder.com`. The authentication mechanism is not finalized yet. Do not copy internal gateway identity headers into client requests.

## 1. Read market constraints

Fetch the market and choose a token from `outcomes[].token_id`:

```bash cURL
curl "https://api.dexbuilder.com/api/v4/event_markets/markets/<market_id>"
```

Then read the public order book:

```bash cURL
curl "https://api.dexbuilder.com/api/v4/event_markets/tokens/<token_id>/order_book?depth=20"
```

Use `min_order_size` and `tick_size` from the response to validate the order before submitting it.

## 2. Submit an order

Create an authenticated request:

```bash cURL
curl -X POST "https://api.dexbuilder.com/api/v4/event_markets/orders" \
  -H "Content-Type: application/json" \
  -H "<authentication-header>: <authentication-value>" \
  --data '{
    "token_id": "<token_id>",
    "side": "BUY",
    "price": "0.52",
    "size": "10",
    "total_cost": "5.20",
    "order_type": "LIMIT",
    "order_mode": "GTC",
    "client_order_id": "client-order-001",
    "post_only": false,
    "sell_all": false,
    "expire_time": 0,
    "biz_type": "event_market"
  }'
```

The authentication placeholder above is intentionally non-operational until the public authentication scheme is finalized. Do not send internal gateway identity headers or other internal headers.

## Request fields

| Field | Description |
| --- | --- |
| `token_id` | Outcome token to trade. |
| `side` | Trade direction, such as `BUY` or `SELL`. |
| `price` | Limit price as a decimal string. |
| `size` | Order size as a decimal string. |
| `total_cost` | Total order cost as a decimal string. |
| `order_type` | Order type defined by the trading service. |
| `order_mode` | Time-in-force or execution mode defined by the trading service. |
| `client_order_id` | Optional client-generated idempotency/reference ID. |
| `post_only` | Whether the order must add liquidity only. |
| `sell_all` | Whether a sell order should use the available position. |
| `expire_time` | Expiration time as Unix seconds when applicable. |
| `biz_type` | Business type for the order. |

## Accepted response

A successful request returns an accepted order reference:

```json
{
  "order_id": "order-123",
  "client_order_id": "client-order-001",
  "status": "ACCEPTED",
  "created_at": 1782753357
}
```

The accepted response does not guarantee that the order has fully matched. Use [Manage Orders](/event-markets/untitled-page-20) to query the order status.

## Validation checklist

Before submitting:

- Confirm the market is `accepting_orders: true`.
- Use a token ID from the market's `outcomes` array.
- Confirm the order size meets `min_order_size`.
- Quantize the price to the market's `tick_size`.
- Keep decimal values as strings to avoid floating-point rounding errors.
- Use an authenticated private request after the authentication scheme is available.
