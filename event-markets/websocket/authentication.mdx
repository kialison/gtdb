Public channels do not require authentication. Private channels require API Key authentication.

The Event Markets endpoint is:

```text
wss://broker.dexbuilder.com/v4/ws/event_markets
```

Do not send internal gateway identity headers. Keep API credentials out of logs and client-side code.

## API Key authentication

API Key authentication uses an API Key and a locally generated HMAC-SHA512 signature. The API Secret is never sent over WebSocket.

Authenticate with the first private operation:

```json
{
  "t": 1787026512123,
  "id": "orders-1",
  "op": "subscribe",
  "ch": "em.orders",
  "payload": {"all": true},
  "auth": {
    "method": "api_key",
    "key": "<api_key>",
    "sign": "<signature>"
  }
}
```

For subscribe and unsubscribe, sign:

```text
channel=<channel>&event=<operation>&time=<timestamp_ms>
```

Use the outer request t as timestamp_ms. Sign the exact UTF-8 message with HMAC-SHA512 and hex-encode the result.

## Pre-authentication

API Key clients may authenticate once before private subscriptions:

```json
{
  "t": 1787026512123,
  "id": "auth-1",
  "op": "auth",
  "ch": "server.sign",
  "payload": {
    "method": "api_key",
    "key": "<api_key>",
    "sign": "<signature>"
  }
}
```

For server.sign, sign the decimal string value of the outer t:

```text
HexEncode(HMAC-SHA512(api_secret, decimal(t)))
```

After successful authentication, later private subscribe and unsubscribe operations on the same connection may omit auth. A connection cannot be rebound to another user.

## Heartbeat

The server sends WebSocket Ping control frames. Standard WebSocket clients should reply with Pong automatically. Clients may also send an application-level ping:

```json
{"t":1787026512123,"id":"ping-1","op":"ping"}
```

The response contains result.status: "success" and result.message: "pong".

## Error codes

| Code | Meaning | Typical cause |
| --- | --- | --- |
| 1 | Invalid request format | Invalid JSON, payload, or auth shape. |
| 2 | Invalid argument | Invalid operation, channel, timestamp, item, depth, or subscription limit. |
| 3 | Server error | Temporary service failure. |
| 4 | Authentication failure | Missing credentials or invalid signature. |

## Reconnection

The server does not retain subscriptions or missed messages after a disconnect.

1. Reconnect with exponential backoff.
2. Authenticate again.
3. Restore public and private subscriptions.
4. Query REST endpoints to recover missed events and current state.
5. Deduplicate using business identifiers and timestamps where applicable.
